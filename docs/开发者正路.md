# 开发者正路：create → registerApp + aios.json → build / pack → sideload

本页写第一版 SDK 的侧载正路。体验编写面的稳定范围以 [体验编写面契约](体验编写面契约.md)（v0.1.0）为准。依据：`packages/glass-cli/src/commands.ts`、`packages/glass/src/manifest.ts`（生成源，来自 `overrides/manifest.ts`）、`packages/glass/src/background/register.ts`（生成源）。

前提：Bun（CLI `engines.bun >= 1.2.0`）；`pack` 需要系统 `zip`；`sideload` 需要 `adb` 和一台已授权的 Android 手机或模拟器，上面装着**可调试**的 AIOS Host（包名 `local.aios.glass`）。

## 1. `aios-glass create`

```
aios-glass create DIR --id local.aios.myapp [--template reference|compatibility|contacts]
```

- 默认模板是 `reference`（`commands.ts` 里 `create(project, id, template = "reference")`）。三个模板的内容见 `templates/`。没有单独叫 "Hello" 的模板；计划里说的 Hello 模板就是这个默认的 `reference` 模板。
- `--id` 必须符合 `defineApp` 的规则：至少三段小写点分（`/^[a-z][a-z0-9]*(?:\.[a-z][a-z0-9]*){2,}$/`），≤120 字符，且不能含上游商标标识。
- 目录必须不存在（`mkdir` 独占创建，不覆盖已有项目）。
- 生成：模板文件、`.toolchain/glass.tgz`（构建 CLI 时 `npm pack` 出来的 `@aios/glass` 0.5.0）、`tsconfig.json`、`package.json`（依赖 `"@aios/glass": "file:.toolchain/glass.tgz"`），并把 `aios.json` 的 `id` 改成你给的 id。
- 不需要 npm registry。

本仓库里的 `aios-glass create` 已包含一行兼容补丁：先 `mkdir` 再拷模板时，不再因为目标目录刚被创建就报 `ERR_FS_CP_EEXIST`。`@aios/glass-cli` 版本仍是 0.2.0。

然后在项目里 `bun install`。

## 2. 写 `registerApp` 与 `aios.json`

### 后台入口 `src/background/index.ts`（必需）

```ts
import {registerApp} from "@aios/glass/background"
import type {Channels} from "../shared/channels"

registerApp<Channels>((session) => {
  session.ui.handle("counter", async ({increment}) => {
    await session.waitForReady()
    const count = Number((await session.storage.get("counter")) ?? 0) + (increment ? 1 : 0)
    if (increment) await session.storage.set("counter", String(count))
    return {count, hostReady: session.ready}
  })
})
```

（简化自 `templates/reference/src/background/index.ts`。）

- `registerApp` 是 `registerMiniapp` 的公共别名，由 `build.ts` 追加到 `src/index.ts` 与 `src/background/index.ts`；`GlassSession` 是 `MiniappSession` 的别名。
- `registerApp(handler, options?)`：`handler(session)` 收到一个会话；能力见 [会话能力](会话能力.md)。
- `registerApp` 另有一种重载：传入 `defineExperience(...)` 的结果（从 `@aios/glass/experience` 引入，见 `register.ts` 第 55 行起）。这是代码型 Experience 路径，已写入 [体验编写面契约](体验编写面契约.md)。下面第 2.1 节有一份只用拟冻结面的示例。

### 2.1 代码型 Experience（`defineExperience`）

会话处理正路仍然是上面的 `registerApp(handler)`。若要走代码型路径，从 `@aios/glass/experience` 引入 `defineExperience`，再把结果交给 `registerApp`。只使用契约里已拟冻结的处理槽和 Session 面；不要调用 `onMaterials` / `onSegment` / `onPeer`、Memory、perception、agent，也不要在 `aios.json` 里写 `actions`（形状保留，不承诺）。

```ts
import {defineExperience} from "@aios/glass/experience"
import {registerApp} from "@aios/glass/background"

const experience = defineExperience({
  onTimer: async (event, session) => {
    session.log.info("timer", {id: event.data.timer_id})
    await session.output.notify("时间到了", {urgency: "normal"})
  },
  onUtterance: async (event, session) => {
    await session.local.set("last", event.data.text)
    return {reply: "已记下"}
  },
})

registerApp(experience)
```

对应的 `aios.json` 可加上已冻结的 `experience` 声明（`schema` 仍为 `1`；`schema_version` 保留 `v1alpha` 这个名）：

```json
{
  "schema": 1,
  "id": "local.aios.myapp",
  "name": "My Experience",
  "version": "1.0.0",
  "entry": {"background": "background/index.js"},
  "capabilities": [],
  "permissions": [],
  "experience": {"schema_version": "v1alpha", "mode": "realtime"}
}
```

### UI 入口（可选）


`aios.json` 写了 `entry.ui` 时，必须是 `ui/index.html`；源文件是 `src/ui/index.html` 与 `src/ui/index.ts`。UI 通过 `@aios/glass/ui` 的 `aios` 全局与后台通信；类型化通道写在 `src/shared/channels.ts`（`declare global { var aios: AiosTyped<Channels> }`）。

### `aios.json`

由 `defineApp`（`packages/glass/src/manifest.ts:218`）校验，只允许下列键：

| 键 | 说明 |
|---|---|
| `schema` | 固定 `1` |
| `id` | 见上 |
| `name` | 非空，≤120 |
| `version` | `x.y.z` |
| `entry` | `{background, ui?}`，安全相对路径 |
| `capabilities` | `[{id, required}]`，`id` ∈ `APP_CAPABILITIES`（12 个：`aios.input`、`aios.display`、`aios.microphone`、`aios.speaker`、`aios.photo`、`aios.gallery`、`aios.video`、`aios.stream`、`aios.wifi`、`aios.led`、`aios.status`、`aios.imu`） |
| `permissions` | `[{id, reason}]`，`id` ∈ `APP_PERMISSIONS`（13 个，`manifest.ts:17`），`reason` 必填 ≤500 |
| `actions` | 可选，≤64 个，供其他应用 / Host 调用的声明动作 |
| `experience` | 可选；Experience 声明，`schema_version` 保留 `v1alpha` 之名，形状已冻结，见 [体验编写面契约](体验编写面契约.md) |

`manifest.ts` 里的注释写明：`location_coarse` 之外的 `phone_state`、`motion`、`status`、`share_with_developer` 在 Host 端还没有授权入口，目前只是"声明"。

## 3. `aios-glass build` / `aios-glass pack`

在项目根执行：

```
aios-glass build
aios-glass keygen key.pem        # 可选，Ed25519 私钥，放在 dist 之外
aios-glass pack [--key key.pem]
```

- `build`：用打包进 CLI 的 TypeScript 5.9.3 做严格类型检查，再用 `Bun.build` 把后台和 UI 打成 IIFE；输出 `dist/`：`aios.json`、`miniapp.json`（Host 清单，`toHostManifest` 生成）、`aios-build.json`（记录 SDK 版本）、入口 JS 与 `ui/index.html`。产物含上游标识会被拒绝。
- `pack`：校验 `dist` 与 `aios.json` 一致（否则要求重新 build），未压缩 ≤128 MB、压缩后 ≤64 MB，产出 `packages/<id>-<version>.zip`。带 `--key` 时加入 `aios-package.json`（逐文件 SHA-256 + Ed25519 签名），并写 `packages/<id>-<version>.zip.release.json`。
- `pack` 依赖系统里的 `zip`。

## 4. `aios-glass sideload`

```
aios-glass sideload packages/<id>-<version>.zip [--device SERIAL] [--wait SECONDS]
```

- 只接受可调试 Host：通过 `adb shell run-as local.aios.glass` 把 zip 写入 Host 私有目录 `files/aios-inbox/<sha256>.zip`，再用 `aios://sideload/<sha256>` 拉起 Host。不需要 root，不上传云端。
- 用户须在 Host 上确认安装。CLI 轮询 `files/aios-inbox/<sha256>.json` 回执，`state: "started"` 才算成功；`error` / `rejected` 报错；默认等 120 秒（1–600）。**仅送达不代表已安装。**
- `adb` 路径可用 `AIOS_ADB` 覆盖。多台设备时需 `--device`。

`sideload` 需要本机 `adb` 和可调试 Host；没有它们时命令会在找不到 adb 处停下。

## 不是正路的东西

- `aios-glass account / publish / catalog`：连接另行部署的目录服务（`--server URL`），属于目录分发，不是写出并调试一个 Experience 所必需。
- `@aios/runtime-client`：Host↔运行时客户端，不在本仓库。
- Console 空白 / 指令 Experience 的发布路径 API，不是本仓库的开发者面。
