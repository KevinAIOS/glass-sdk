## 1. 这份契约钉什么

出现在稳定面里，只保证形状被冻结，不保证每一台 Host、每一副眼镜都已经实现，也不保证云侧服务已经开通。这与设备契约「词表不是设备支持声明」是同一原则，但两份契约钉的不是同一条边界。

本契约不是把约 600 个可对外公布 API 一次发出去，也不是 Host↔眼镜的设备契约，也不是 Host↔Runtime 契约。另有导出维度（101 个去重值导出、246 个仅类型导出）已按同一套桶分类，与主盘点不相加，不另计入下面的 284。

若对照公开／留云分层里的 A / B / C / D，那是内容分层代号（始终留云 / 首版可开 / 后续可开代码 / 整仓不开放），不是工作流程，也不是授权流程。Memory 服务与数据、市场、账号密钥、运维 Admin、未脱敏遥测属于始终留云。

## 3. 与已公开仓的边界

- https://github.com/KevinAIOS/glass-contract 钉的是 Host 和眼镜怎么说话（75 个操作：50 条命令 + 25 个事件，另有设备侧 CapabilityId 17、PermissionId 12、ErrorCode 17）。本契约不重冻、不改写那一份。设备词表在本契约里全部归入「明确不进」。
- 本仓库是第一版 SDK 与样例的公开快照，并发布本体验编写面契约。体验编写面契约以本文为准，发布在本仓库，不另建第三座公开仓。
- 私有 `KevinAIOS/AIOSGlass` 仍是真源，整仓不开放，本契约不改变该私有仓的许可或可见性。
- `@aios/runtime-client` 与 Host↔Runtime 属于总计划第 4 步，不进本契约。

### 三套词表，不要合并

| 词表 | 数量 | 本契约处置 |
|---|---:|---|
| `aios.json` 的 `APP_CAPABILITIES` / `APP_PERMISSIONS` | 12 / 13 | 拟冻结（声明与校验，不冻已授权或已实现） |

两边都有的拼写（如 `aios.display`、`aios.permission.motion`）仍是两套标识符，不要当成同一个。设备侧独有如 `aios.ota`、`aios.permission.device`；代码型独有如 `store`、`memory`、`perception.frames`。设备契约另有 17 个 ErrorCode 与 75 个操作，已在第 1 步冻结，不列入本编写面的 401 项，也不在本契约中重冻。

## 9. 未核对项与完整性限制

下列限制写进本契约，但不构成「已经保证的行为」。不得把纸面样例当成已经跑通。本契约对应的稳定面已用会话处理与代码型两条路径做过类型检查和 in-tree `aios-glass build`；`pack` 需要系统 `zip`，本契约不把缺少 `zip` 时的替代实现当成真实 `pack`。真机 `sideload`、Native AAR 构建、以及 Host 是否接受代码型 Experience，都不是本契约已经证实的行为。

- `stream` 守护进程侧「v1 未直播」：SDK 只做转发（`packages/glass/src/modules/stream.ts`），本仓库没有守护进程源码。详见 [稳定面与 v1 空操作](稳定面与v1空操作.md) §4。
- Host 对未配置服务类操作实际返回的错误码：`SERVICE_NOT_CONFIGURED` 只出现在生成时注入的注释，`MiniappErrorCode` 中没有这个码。
- `transcription` / `translation` / TTS 是否需要单独配置服务：注释表明依赖手机或云侧，尚未单独核对。
- Native AAR 与 Native 样例：本仓库公开快照未附带已构建的 AAR；构建需要 JDK 17 与 Android SDK，见 [构建](构建.md)、[Native SDK](Native-SDK.md)。
- 真机 `sideload` 与 Host 回执需要 `adb` 和可调试的 AIOS Host，见 [开发者正路](开发者正路.md)。
- `aios-glass pack` 依赖系统 `zip`。
- Bun 1.2.x（CLI `engines` 下限）下的 `create` 行为未单独验证（当前文档依据的运行时是 Bun 1.4.x 一代）。
- 代码型 Experience 被 Host 接受（`bindExperience` / Hub 调用）尚未作为已跑通的行为写入本契约。开发者应使用 `defineExperience` + `registerApp`，不要直接依赖绑定函数。
